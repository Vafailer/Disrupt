README и ранние планы местами описывают состояние предыдущих веток. Админку, scheduler и аудиоввод заново делать не требуется. Опорные источники для текущего состояния находятся в коде, PR #12–14 и server-deploy-result-v1.md.

## Что ещё нужно для пилота

На стороне Марка остаются HTTPS после появления DNS, открытие и закрытие регистрации, запуск единственного бота, личное включение LLM worker владельцем и пользовательская проверка качества. Реальное STT требует подтверждённого протокола программного шлюза. Кандидат уже есть в app/speech.py, но не подтверждает живое распознавание.

В бэклоге ядра остаются пользовательская обратная связь, удаление и экспорт личных данных, тарифы и денежные бюджеты. CSV админки уже реализован и не является экспортом личных заметок. Эти задачи затрагивают файлы Марка и требуют отдельного контракта. PWA и offline отложены после MVP. Постоянный перенос копий и внешние оповещения требуют выбранного хранилища и канала уведомлений.

## Задачи Андрея без домена и секретов

1. Независимо проверить интегрированную сборку на отдельном локальном mock-окружении. Пройти два аккаунта, привязку через подменённый Telegram, ручную запись, синтетический WAV, скачивание оригинала, напоминание и доступ к админке. Изучить существующие тесты и покрыть обнаруженные пробелы. Записать результат с SHA и воспроизводимыми шагами. Баги в ядре передать Марку с файлом, строкой и сценарием.
2. Уточнить сообщения Telegram. В текущем /help голос предложен без объяснения, что живое STT выключено. Пользователь должен понимать, где посмотреть статус, чем /save отличается от обработки ИИ, как закончить привязку в вебе и что сохранённый оригинал не означает готовую расшифровку. Согласованный API и идемпотентность сохранить. Проверять с MockTransport.
3. Пройти админку в полноценном браузере на узком экране и с клавиатурой. Проверить фильтры дат, длинные таблицы, пагинацию, CSV, потерю сессии и роли, loading/error/empty, null и zero. DOM-тесты уже покрывают много случаев, но не подтверждают внешний вид и реальное управление браузером. Исправлять найденные проблемы в admin.html/js/css.
4. Подготовить план ревью и будущего объединения PR. Проверить историю и пересечения файлов, особенно CI и общие runtime-файлы. Список draft PR не равен списку недоделанных модулей. Результат этой задачи должен быть предложением для обоих разработчиков, без слияния веток.
