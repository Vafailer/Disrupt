# Аудиомодуль. Передача Марку

Ветка codex/audio-intake-v1, основана на adfdcac. Ветка ядра не объединялась.
Проверяемое ядро — 80002342180fb07ea3c95eca594f3b7c7ff2a82f.

## Реализовано

app/audio_storage.py содержит подтверждённые AudioInfo, StoredAudio, AudioStorage и ошибки. Конструктор и ключ UUID.audio соответствуют договорённости. Оригинал сохраняется неизменным, с fsync и атомарной публикацией без перезаписи. Незавершённый временный файл удаляется; опубликованный файл при неопределённом результате commit остаётся. Сборщика осиротевших файлов нет.

Поддерживаются Ogg/Opus, WAV/PCM и WebM/Opus. Проверяются контейнер, один поток, кодек, полное декодирование и фактическое число сэмплов. Лимиты 10 МиБ и 180 секунд включительно. MIME и исходное имя не используются для определения формата. Для Ogg проверяется целостность границ страниц и окончание потока; для WAV — заявленный размер RIFF; для WebM — DocType EBML.

app/audio_process.py запускает декодер с лимитом CPU 20 секунд, 64 файловых дескриптора. На Linux дополнительно действует лимит адресного пространства 512 МиБ. На macOS этот лимит памяти не применяется, локальная проверка не доказывает изоляцию памяти Linux. Одновременно допускаются два декодера на процесс API; при занятых слотах возвращается временный 503. В родительском процессе ограничены время 25 секунд, объём stdout и размер отдельной аллокации FFmpeg. stderr декодера не попадает в логи. Это ограничения ресурсов, не полноценная песочница ОС.

app/routes/audio.py содержит build_router(database, settings, storage, create_audio_capture). Реализованы Telegram voice, браузерный POST /api/v1/captures/audio и защищённое скачивание. Авторизация проверяется перед разбором формы. В браузере обязательны CSRF и Idempotency-Key. Повторы не декодируются повторно. Telegram использует общий process_update. Перед декодированием и публикацией под блокировкой аккаунта проверяется свободное место в очереди, чтобы повторы 429 не заполняли диск осиротевшими файлами. create_audio_capture вызывается без commit, ответ выдаётся после фиксации БД.

main.py, модели, миграции, worker и requirements не изменены. Марк подключает router и хранилище по прежней договорённости. До подключения маршруты не появляются в приложении. Автоматического обращения к STT или Cloud.ru нет.

## Проверки

Тесты tests/test_audio_storage.py создают синтетические файлы, вызывают настоящий FFmpeg/FFprobe и проверяют все три формата, повреждения, несколько потоков, неверный кодек, лимиты, таймаут, отсутствие декодера, fsync и защиту пути. Записей людей в фикстурах нет.

Тесты tests/test_audio_routes.py подключают router только в тестовое приложение. Проверяют авторизацию, идемпотентность, конфликт с текстом, отказ очереди без закрепления Inbox, сохранность файла при сбое commit и STT, скачивание владельцем. Конкурентные веб/Telegram загрузки отдельно проверяются на PostgreSQL в CI.

Локально для ядра 8000234 полный прогон до добавления ограничения параллелизма прошёл с 245 тестами, четыре PostgreSQL-проверки пропущены. Линтер проходит. Локальный декодер FFmpeg/FFprobe 9.0.2, Apple Silicon, сборка Martin Riedl. Источник https://ffmpeg.martin-riedl.de/ . В Linux образ и CI устанавливают системный пакет ffmpeg, фактическая версия выводится в логах CI.

CI audio-core выгружает точный коммит ядра во временную папку и копирует туда только наши модули и тесты. Слияния веток нет. После интеграции этот временный шаг заменить проверкой общего checkout. На исходной ветке тест аудиомаршрутов явно пропускается из-за отсутствия моделей ядра; решающая проверка находится в audio-core.

Dockerfile устанавливает ffmpeg/ffprobe и создаёт закрытый каталог /app/data/audio для пользователя notes. Оба Compose-файла монтируют постоянный audio-originals в API и read-only в worker. Не изменены настройки доступа к модели. Production-конфигурация не запускалась, секреты не читались. Резервное копирование должно включать этот том вместе с БД; очистку файлов пока не запускать.

Живой Telegram, реальный STT и сервер не проверены. Образ и PostgreSQL проверяются отдельно в CI. Статус проверять по SHA опубликованной ветки.
