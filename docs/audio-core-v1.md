# Аудио v1. Решения и готовность ядра

Прочитан `docs/audio-integration-v1.md` из `codex/audio-intake-v1`, коммит `add1673228250d9a8f40e40e303af3cad7e3ff6c`. Предложенный контракт принимаем с уточнениями ниже. Можно начинать модуль и тесты без нового круга согласования.

Наша ветка `feature/audio-stt-core-v1` создана от проверенной `integration/telegram-core-v1`, коммит `adfdcac9168ab5b75877b087619f85cbea723289`. Ветки пока не объединены.

## Интерфейсы

`AudioInfo`, `StoredAudio` и четыре метода `AudioStorage` принимаем. `StagedAudio` остаётся внутренним типом вашего модуля. Ядро не открывает его путь и не импортирует конкретные классы хранилища. Типы для ядра находятся в `app/audio_contracts.py`.

Для подключения используем такой конструктор.

```python
AudioStorage(
    root,
    *,
    ffmpeg_path="ffmpeg",
    ffprobe_path="ffprobe",
    read_only=False,
)
```

Ключ опубликованного файла имеет вид `{capture_id}.audio`. `capture_id` является каноническим UUID, созданным сервером. Расширение одинаковое для всех контейнеров, действительный формат хранится отдельно. При `read_only=True` разрешено только `open_original`. `AudioStorageUnavailable` наследуется от `OSError`, чтобы worker мог вернуть безопасный код сбоя без импорта вашего модуля.

Фабрику `build_router(database, settings, storage, create_audio_capture)` принимаем. `database` является существующей FastAPI-зависимостью, которая выдаёт SQLAlchemy Session. На один запрос используется одна сессия.

Функция `app.services.create_audio_capture` уже реализована с предложенной сигнатурой. Она создаёт Capture, Job и событие `capture_saved`, делает flush, но не commit. Идентификатор новой Capture равен переданному UUID. Функция не пишет файлы и не вызывает STT.

В Capture добавлены `audio_sha256` и `audio_media_type`. Миграция `39e7b64d210a` идёт после `2c7a84b1e903`. Старые текстовые записи сохраняются, новые поля у них равны NULL. Других миграций аудиомодулю создавать не нужно.

Повтор с тем же ключом и теми же сведениями возвращает существующий Job, даже после обработки. Другой исходник, тип ввода или канал даёт 409. Насыщенная очередь возвращает обычный HTTPException 429, без IntegrationRejection. Этот временный отказ не должен оставаться в Inbox навсегда.

## Форматы и ограничения

Первый набор включает Ogg/Opus, WAV/PCM и WebM/Opus. WebM нужен для записи в браузере. Канонические media_type соответственно `audio/ogg`, `audio/wav` и `audio/webm`. Имя файла и MIME запроса по-прежнему ничего не доказывают.

Лимиты остаются прежними, 10 МиБ и 180 секунд включительно. Проверку реального контейнера, одного аудиопотока, полного декодирования и длительности по сэмплам выполняет ваш модуль. Ядро дополнительно проверяет пределы и корректность метаданных, но не заменяет декодер.

Порядок stage, inspect, publish, транзакция Inbox и правила сохранности оригинала принимаем. При неизвестном результате commit опубликованный файл сразу не удаляем. Автоматической очистки в этом блоке нет.

## Маршруты

`POST /internal/v1/telegram/voice` остаётся по предложенному контракту. Используйте `process_update` и `telegram_identity` без изменения их интерфейсов. Внутренняя модель для digest содержит Telegram ID, `processing_mode="ai"` и `audio_sha256`. Повтор читает исходные байты для проверки SHA-256, но не декодирует и не публикует их заново. Идентичность update общая с текстом, привязкой и кнопками.

Веб-загрузка входит в этот же router, чтобы не создавать второй аудиомаршрут.

```http
POST /api/v1/captures/audio
Cookie: notes_session=...
X-CSRF-Token: ...
Idempotency-Key: ...
Content-Type: multipart/form-data; boundary=...
```

Ровно одно поле `audio` и одно поле `processing_mode` со значением `ai`. Другие поля и дубликаты отклоняются. Владелец определяется через `get_login_session(request, db, write=True)`, не берётся из формы. Ключ соответствует тому же шаблону, что для текстовых записей, от 1 до 100 символов `[A-Za-z0-9_.:-]`.

В обоих POST проверяйте авторизацию до разбора формы и работы с файлом. Используйте Request, не автоматический разбор File/Form до проверки доступа. BodyLimit ограничивает фактическое тело запроса, включая multipart и chunked.

Веб возвращает 202 с результатом `job_view(db, job)` только после commit. Точный повтор тоже возвращает 202 и текущее состояние того же задания. До inspect/publish сериализуйте запросы владельца через `lock_account`, проверьте существующую Capture по владельцу и ключу. Совпавшие SHA-256 и режим позволяют вернуть задание без повторного декодирования. Другие байты или тип ввода возвращают 409. Браузерные ошибки используют существующее тело `{"detail": "..."}`; коды HTTP те же, что у голосового Telegram-маршрута.

Скачивание оставляем по адресу `GET /api/v1/captures/{capture_id}/audio`. Сначала браузерная сессия и владелец, затем открытие файла. Чужая, отсутствующая или текстовая Capture даёт 404. Ошибка STT не блокирует скачивание. Ответ содержит исходные байты, `Content-Disposition: attachment`, `Cache-Control: no-store`, `X-Content-Type-Options: nosniff`. Имя скачивания создаётся сервером по UUID и проверенному формату. Внутренний ключ и путь не возвращаются.

## Worker и подключение

Worker принимает `audio_storage` и `speech_provider` как отдельные зависимости. Интерфейс STT простой.

```python
transcribe(source: BinaryIO, *, media_type: str) -> str
```

В STT передаётся поток оригинала с проверенным media_type. Если будущему провайдеру потребуется преобразование, оно выполняется отдельно и не меняет сохранённый оригинал.

До STT `original_text=""`, `transcript=NULL`. Первую валидную расшифровку worker сохраняет в обоих полях отдельным commit до LLM. `transcript_version` остаётся 1. Пустой ответ, NUL или текст длиннее 12000 символов отклоняются. Ошибка LLM сохраняет расшифровку и исходный файл. Просроченный lease не позволяет сохранить запоздалый результат STT или запустить LLM.

Реальный STT пока не настроен. Без явно переданного провайдера задание завершается с `stt_not_configured`, без обращения в LLM с пустым текстом. `MockSpeechProvider` принимает заданный текст только для синтетических проверок. Настоящий Cloud.ru не вызываем, его ключ не читаем.

Настройки уже добавлены.

| Поле Settings | Переменная окружения | По умолчанию |
|---|---|---|
| audio_storage_path | NOTES_AUDIO_STORAGE_PATH | data/audio |
| audio_ffmpeg_path | NOTES_AUDIO_FFMPEG_PATH | ffmpeg |
| audio_ffprobe_path | NOTES_AUDIO_FFPROBE_PATH | ffprobe |

Python-зависимость `python-multipart==0.0.32` зафиксирована. После публикации вашего модуля я создам storage для API, подключу router в main и передам отдельный экземпляр с `read_only=True` в worker. Сейчас этих HTTP-маршрутов в приложении ещё нет, в OpenAPI они помечены как contract-only.

Декодер и общий том остаются вашим следующим блоком. В PR укажите фактическую версию ffmpeg/ffprobe и добавьте установку в образ и CI вместе с тестами настоящих синтетических файлов. При интеграции проверим доступ API на запись и worker на чтение. Повторного разрешения на эти обычные изменения ждать не нужно.
