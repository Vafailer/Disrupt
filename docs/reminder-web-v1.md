# Напоминания в вебе

Ветка `feature/reminder-web-v1` создана от `feature/reminder-delivery-v1`, коммит `73f47d54d290fe004958fa7eb1d83c039d6e4902`. Работа вернулась в задачи Марка. Адаптер бота, scheduler, аудиохранилище, модели и миграции не менялись. Новая форма использует уже готовый API напоминаний.

## Как пользоваться

Откройте заметку. В разделе «Напоминания» можно добавить уведомление ко всей записи. У открытой задачи также есть кнопка «Напомнить». Закрытые задачи и идеи не предлагаются как получатели напоминания.

Форма работает так, как описано в разделе «Быстрая форма» ниже. Время всегда относится к выбранному поясу, а не к месту, где открыт браузер. Сервер возвращает точный UTC и смещение, кнопка «Напомнить» активна только для найденного будущего времени. Расчёт времени сам ничего не сохраняет и не запускает ИИ.

Если при переводе часов выбранное время наступит дважды, форма покажет оба смещения UTC. Нужно выбрать одно. Если такого времени нет из-за перевода часов, сервер предложит выбрать другое. Прошедшее время не принимается. Перед сохранением ядро ещё раз проверяет, что срок в будущем.

Напоминание можно сохранить до привязки Telegram. Форма прямо показывает, что для доставки нужен доступный бот. Если связь отключена или заблокирована, наличие привязки не выдаётся за готовность доставки. Кнопка «Подключить Telegram» видна, только пока доступного Telegram нет, и открывает существующий раздел привязки.

## Быстрая форма

Нажмите «Добавить напоминание» и выберите вариант: «Через час», «Сегодня в 19:00» (скрыт после 18:30), «Завтра в 9:00», «В понедельник в 9:00», «Через неделю» или «Другое время». Выбор сразу заполняет дату и время и считает срок. Для «Другого времени» появляются поля даты и времени с шагом пять минут, по умолчанию завтра в 9:00. Скрытое поле `#reminder-local` хранит значение `YYYY-MM-DDTHH:MM:00` и остаётся источником правды для остальной логики.

Часовой пояс показан одной строкой, например «Москва (Europe/Moscow)». Берётся последний подтверждённый пояс, иначе пояс браузера, иначе Europe/Moscow. Ссылка «Изменить» открывает поле пояса со списком подсказок.

Кнопки «Проверить время» нет. Срок считается сам через 300 мс после последнего изменения даты, времени или пояса. Выбор варианта считает сразу. Ответ, который пришёл после более новой правки, игнорируется. Под формой написано, например, «Напомню в субботу, 11 октября, в 9:00 (Москва)» и текст напоминания. Если время прошло, форма пишет «Это время уже прошло. Выберите другое.» При двойном времени из-за перевода часов появляется выбор «Первый раз» или «Второй раз» со смещением UTC. Кнопка «Напомнить» (при правке «Сохранить изменения») нажимается только после этого, и это нажатие остаётся подтверждением. Кнопка «Отмена» закрывает форму.

Поле «Напомнить о» показано, только если в заметке есть открытые задачи. Иначе напоминание ставится к заметке целиком.

Список состоит из компактных строк: дата и время («Сб, 11 окт, 9:00»), текст, небольшая метка статуса и тихие кнопки «Изменить» и «Отменить». «Обновить» вынесено в заголовок списка.

## Список и правки

Список показывает текст, выбранную зону, задачу или заметку и состояние доставки. Есть изменение и отмена. Список разбит на страницы по двадцать записей, статусы обновляются каждые пятнадцать секунд в видимой вкладке. Ручное обновление возвращает к первой странице. Ошибка чтения показывает сообщение, а не пустой список с обещанием, что напоминаний нет.

При изменении сохраняется текущая generation. Если другая вкладка уже изменила напоминание, поля остаются в форме. Можно показать текущий вариант, сравнить и явно продолжить с его версией. После этого время нужно проверить заново. Скрытого повторного PATCH нет.

Если создание сохранилось, но ответ потерян, форма оставляет тот же Idempotency-Key, текст и время. Повтор подтверждения не создаёт дубль. До получения ответа поля закрыты от изменения. Закрытие такой формы требует предупреждения, после него список загружается заново. Ключ живёт в этой странице браузера. После перезагрузки сначала проверьте список перед новым созданием.

После потери ответа на правку форма сначала читает текущий вариант. Если поколение и все отправленные поля совпадают с результатом нашей правки, сохранение подтверждается без нового PATCH. В остальных случаях пользователь сравнивает варианты и явно выбирает текущую версию перед повторной правкой.

Отмена использует generation и существующий идемпотентный API. Если запись изменилась, форма обновит список и предложит проверить новый вариант. Она не отменяет новую редакцию автоматически. При unknown или previous_attempt_unknown показано предупреждение, что сообщение могло уйти. Новая дата и отмена не отзывают уже отправленное сообщение.

Черновик напоминания учитывается вместе с правками заметки и расшифровки. Переход на другую запись и выход предупреждают о потере данных. Сохранение заметки не стирает черновик напоминания. Пока запрос сохранения идёт, переходы закрыты. Запоздалый ответ другой заметки не заменяет текущий список.

## Добавления к API

`POST /api/v1/reminders/resolve-time` требует сессию, X-CSRF-Token и подходящий Origin. Тело содержит local_time без смещения и timezone. Ответ содержит те же поля, ambiguous и choices. Каждый вариант имеет scheduled_at в UTC, local_at со смещением, utc_offset и is_future. При ambiguous даже единственный оставшийся будущий вариант нужно выбрать явно. Ошибки времени возвращают 422. Метод не создаёт событий активности, заданий или Outbox.

В `GET /api/v1/telegram/links` у собственных identities добавлены notifications_enabled и delivery_status. Старые поля сохранены. Бот этот браузерный метод не использует.

Полная OpenAPI и пример запроса обновлены командой `PYTHONPATH=. python scripts/export_contract.py`. Формат существующих create/edit/cancel и внутренних методов доставки не менялся.

Расчёт времени использует ZoneInfo и обратное преобразование через UTC. Проверки включают обычный часовой пояс, смещение на 45 минут, секунды, два возможных времени, пропуск часа, получасовой переход и пропущенный календарный день. Правила fold описаны в [документации Python](https://docs.python.org/3/library/zoneinfo.html).

## Проверки

```sh
python -m pytest -q
python -m ruff check app tests migrations scripts telegram_adapter
NODE_PATH=/path/to/node_modules node tests/web_reminders.cjs
```

DOM-тест проверяет быстрые варианты на фиксированных часах, автоматический расчёт с задержкой, прошедшее время, скрытый выбор цели, подтверждение в выбранном поясе, выбор задачи, сохранение черновиков, повтор создания после потерянного ответа, восстановление результата правки, конфликт generation, unknown, отмену, выбор смещения UTC, пагинацию и запоздалые ответы. Новый тест добавлен в CI рядом с проверками текста и аудио.

Локально 6 октября прошли 356 тестов. Семь проверок PostgreSQL пропущены, локального сервера БД нет. Ruff, проверки DOM текста, аудио и напоминаний прошли. Полный результат CI с PostgreSQL и точным SHA будет записан в PR.

Реальный Telegram и срок доставки здесь не проверялись. Доставка с подменённым транспортом уже проверена в предыдущей ветке. STT, API бизнес-статистики, введение, обратная связь, удаление и экспорт остаются следующими задачами нашей стороны. Админский экран и эксплуатация остаются за коллегой.
