# Голос и текстовый результат

Ветка `feature/voice-text-replies-v1` основана на опубликованном отчёте установленной сборки `7403f65`, код приложения соответствует `7cfc172`. Ветки коллеги не объединялись.

Выбрана модель `whisper-large-v3`. Разрешённый владельцем GET каталога шлюза подтвердил этот ID. Публичная схема `https://shared1.multitool.works:4000/openapi.json` содержит `/v1/audio/transcriptions` с multipart. Публичный каталог Cloud.ru описывает Whisper как Audio-to-Text, но имя в шлюзе отличается от официального `openai/whisper-large-v3`.

Первый разрешённый STT-запрос собственной записи владельца вернул HTTP 400 за 449 мс. Исходник WebM, 16,14 секунды, остался неизменным. Попытка записана в ProviderUsage и увеличила общий счётчик с четырёх до пяти. Расшифровка не получена, автоматического повтора нет. Точная причина отказа не подтверждена.

## Что подготовлено

- Worker получает `NOTES_STT_ENABLED`, `NOTES_STT_PROTOCOL_CONFIRMED`, `NOTES_STT_MODEL`. По умолчанию STT выключен. Такая передача настроек есть и в отдельной ветке коллеги; её диагностический CLI не переносился, поскольку он обходит бюджет и выводит часть расшифровки.
- Перед STT копия аудио переводится в WAV, 16 кГц, один канал. Оригинал не изменяется. Декодер ограничен временем, CPU, памятью, длительностью и размером вывода. Запрос содержит model, file и language=ru. В ответе проверяется text.
- После успешного STT расшифровка сохраняется до LLM. Lease продлевается для второго этапа; уже истёкший lease не возобновляется. Одна голосовая ИИ-запись занимает два слота, STT и LLM.
- Готовый результат входящей записи Telegram отправляется текстом через существующие claim/authorize/result и журнал адаптера. Бот не ждёт ИИ внутри polling и не запускает модель. Веб показывает ту же заметку.
- Outbox связывается с исходными job, bot и chat при сохранении записи. Уникальный job_id исключает повторное создание доставки. Перед отправкой проверяются владелец, готовая заметка и действующая связь. Веб-записи не рассылаются в Telegram автоматически.
- Неопределённый исход отправки не повторяется. Повтор допустим только при подтверждённом отказе Telegram с retry_after. В сообщении нет parse_mode или кнопки выполнения задачи. Длина ограничена по UTF-16, полный результат открывается ссылкой.

Миграция `e61f893ac204` следует за `d84f210ac937`. Существующие напоминания сохраняются. Автоматический downgrade запрещён при наличии состояния доставки результатов, чтобы не потерять его.

## Проверка

Ruff и генерация контракта проверяются без ключа. На Windows прошли 65 целевых тестов, две проверки Linux-декодера и POSIX-журнала пропущены. Нужен полный Linux/CI прогон, включая миграцию PostgreSQL и оба вида доставки. Синтетические данные не добавляются в пилот.

`python -m app.stt_readiness --capture-id UUID --model whisper-large-v3 --allow-live-probe` выполняет ровно одну проверку WAV в worker. Receipt и оба счётчика фиксируются до HTTP, повтор этого probe для capture запрещён. Вывод содержит только статус, фиксированную категорию ошибки, длительность и длину текста. Ключ, тело ошибки и расшифровка не выводятся.

Для следующего пробного STT требуется новое разрешение владельца, поскольку разрешённая первая попытка уже использована. До подтверждения STT на VPS остаётся выключенным, установленная текстовая обработка работает. Ключ хранится в существующем secret-файле ядра, не передаётся боту или в Git.

Владелец отдельно разрешил второй probe. WAV без language вернул HTTP 400 за 658 мс; безопасная диагностика указала категорию language. Счётчик вырос до шести. Добавлен language=ru, response_format не передаётся. Живая проверка этого варианта требует нового разрешения. Первый запуск второго probe отказал из-за относительного пути к аудио до резервирования и HTTP; путь исправлен через NOTES_AUDIO_STORAGE_PATH=/app/data/audio в одноразовом контейнере.

Третья попытка отдельно разрешена владельцем вместе с включением новых голосовых записей при успехе. WAV с language=ru успешно распознан: 154 символа, HTTP-этап 449 мс. Ключ и текст не выводились. Учтены семь попыток. До установки проверенной общей сборки основной STT остаётся выключенным.

Изолированный Linux-прогон дал 525 passed и 10 skipped. Единственное падение вызвано запретом записи в data/audio при проверке контракта на readonly mount. Декодер и журнал прошли. Для этой проверки требуется отдельный tmpfs data, без доступа к рабочему аудиотому.

После добавления tmpfs и изолированной PostgreSQL прошли 535 тестов. Один новый тест имел неполную синтетическую Note без обязательного provider; фикстура исправлена. Код приложения при этом не менялся, нужна повторная проверка этого теста.
