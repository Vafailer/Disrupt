# Почта для регистрации

SMTP.BZ подтверждён владельцем. Из-за блокировки SMTP-портов у VDSina планируется HTTPS API. TLS api.smtp.bz:443 проверен с российского VPS, авторизация и доставка ещё не проверялись. Текущий сайт использует логин и пароль, почтовой регистрации пока нет.

Ветка `feature/email-auth-v1` отдельная, база выпуска focus UI. Перед изменением модели User и миграций согласовать пересечение с работой Андрея над Telegram Login. Сохранять существующие аккаунты, user_id и привязки.

Владелец запускает `save-smtp-bz-key.cmd` и вводит API-ключ скрыто. Скрипт использует существующий ssh-agent и не пересылает его. Ключ передаётся через SSH stdin только на ядро, сохраняется в `secrets/smtp_bz_api_key.txt` с правами 0400 для UID 1000. Существующий файл не перезаписывается. Содержимое SSH-ключа не читается. В Git и Хельсинки API-ключ не попадает. Скрипт не проверяет ключ у провайдера и не отправляет письма.

Первая версия не сохраняла ключ из-за потери кавычек в Windows PowerShell. Вместо Python-кода в аргументе SSH теперь сначала передаётся публичный файл обработчика через stdin, затем запускается его путь без кавычек. Значение ключа остаётся только в stdin отдельного процесса. Исходный секрет не был сохранён или показан.

Полная проверка `powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/save-smtp-bz-key.ps1 -SelfTest` прошла через реальный SSH. Подставное значение сохранялось только в TemporaryDirectory. Проверены права 0400 и UID/GID 1000, запрет перезаписи и пяти некорректных значений. Настоящий secret-файл после проверки отсутствовал. Письма и запросы API не отправлялись. Скрипт проверен парсером PowerShell и Ruff.

После сохранения ключа нужно определить адрес отправителя, реализовать почтовую очередь, подтверждение email и восстановление пароля. Проверки кода используют mock и отдельную базу. Фактическую доставку подтверждать отдельной проверкой владельца.

## Проверка 10 октября

Владелец сохранил SMTP.BZ API-ключ. Файл на ядре непустой, mode 0400, UID/GID 1000. Авторизация GET /user/domain возвращает 200, береста-домен есть в аккаунте, SPF и DKIM true. Значение ключа не выводилось и не передавалось в Хельсинки.

Подготовлен отдельный HTTPS-транспорт `app/smtp_bz.py`. 15 проверок с подменённым HTTP прошли, Ruff зелёный. Проверены multipart, URL-encoded и JSON, ограничение ответа, HTML-экранирование, безопасные ошибки, отсутствие редиректов и автоповторов. В рабочий API транспорт ещё не включён.

Владелец разрешил одно тестовое письмо на свой адрес. Отправка не удалась: четыре последовательные проверки вернули явный HTTP 400, принятых писем нет. После первого отказа проверен пустой журнал сервиса; альтернативные формы и контроль после повторной верификации допускались только при явном 400 всех предыдущих проверок. Последний безопасный диагностический набор — domain, verified, not. На неопределённом результате и после принятия probe запрещает повтор.

POST /user/domain/verify вернул result true и вложенный moderation true, но API отправки по-прежнему отклоняет домен. Значение moderation пока не трактуется как одобрение или ожидание без пояснения сервиса. Причина расхождения требует проверки SMTP.BZ. Пробы остановлены, почтовая регистрация не включена, доставка не подтверждена. Получатель и API-ключ в Git не записаны; receipts без адреса и тела находятся отдельно в .local на ядре.

В origin/tmp/security-debug уже есть работа коллеги над Telegram, почтой и восстановлением. Эта ветка не объединялась и на VPS не устанавливалась. Модели аккаунта и миграции в нашей почтовой ветке не меняются; подключение HTTPS-транспорта согласовать с его app/mailer.py после передачи стабильного SHA.
