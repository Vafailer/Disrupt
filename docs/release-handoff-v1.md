## Проверка и развёртывание

Проверить общую сборку с mock, PostgreSQL, миграциями, Ruff, контрактом и DOM-наборами, включая очередь и onboarding. Проверить вход и регистрацию, пустой поиск и категорию, привязку Telegram, выход и вход другим аккаунтом, ширины 360/390 px. Синтетические данные держать в отдельной базе.

Перед миграцией сделать согласованную age-копию штатным координатором. Он сохраняет БД, оригиналы аудио и состояние удалённого бота. Новую копию скачать на ПК и сверить SHA. Ключ расшифровки хранится только на ПК Марка. Не запускать отправителя Telegram при изолированном восстановлении. Последняя скачанная копия до подключения модели не содержит новых ИИ-заметок.

На обоих VPS установить один SHA интеграционной ветки. Сохранить секреты и `.env.production`, пределы 100/20 и бессрочную регистрацию. Перед пересозданием worker дождаться завершения текущего задания; не прерывать оплачиваемый запрос. Idle-worker штатно завершает SIGINT, обработчик SIGTERM отсутствует. Оставить один адаптер и один worker, существующие тома и originals.

Обычная сборка на РФ ранее упёрлась в недоступный HTTP-репозиторий Debian. Есть `deploy/Dockerfile.runtime-reuse` и `deploy/compose.runtime-reuse.yaml`. Использовать их только при совпадении `requirements.txt` с рабочим базовым образом. Локальная база `beresta-runtime-base:verified-format-20261009`. При новых зависимостях требуется обычная полноценная сборка.

После установки проверить health, миграцию, HTTPS, авторизацию внутреннего API из контейнера бота, 401 без секрета, публичные 404 для `/internal`, отсутствие публичного 18000 и порта БД. API должен оставаться на `10.77.0.1:18000`. Сохранить Docker firewall, WireGuard и SSH. Worker использует профиль `owner-live` и `restart=no`; не включать безлимитный автозапуск после перезагрузки.

## Ограничения и оставшиеся проверки

Не искать, читать, выводить или переносить значение ключа Cloud.ru. Марк разрешил работающий текстовый worker и увеличение лимита. Каталог моделей, баланс и реальные STT-запросы не разрешались. Автотесты используют подменённый транспорт. Не создавать реальные запросы ради проверки и не повторять старые неуспешные задания автоматически.

Приём и хранение аудио есть, автоматическое STT не готово. Одна настоящая привязка Telegram существует, полный сценарий доставки напоминания ещё не подтверждён. Администратора назначить позже по просьбе Марка, внешние уведомления мониторинга пока не настроены.

Финальную живую приёмку провести с владельцем. Вход, запись, результат в вебе, запись через Telegram, подтверждённое время напоминания, доставка и выполнение задачи. Отдельно оценить качество ИИ. Не объявлять голос готовым.

SSH root/22 по существующим ключам. Доступ к РФ иногда работает только через Хельсинки и WireGuard с `HostKeyAlias=178.217.98.101` и `IPQoS=none`. SSH-agent не пересылать, приватный ключ ПК не копировать. Если в среде Андрея доступа нет, закончить интеграцию и CI, затем запросить доступ у Марка.
