## Проверки

На российском VPS полный прогон дал `460 passed`. PostgreSQL, заметки, аудио, напоминания, STT-кандидат и Telegram-адаптер проверялись с mock или подменённым HTTP-транспортом. Отдельная синтетическая заметка, WAV и напоминание созданы в проекте `beresta-verify`. Оригинал WAV скачан без изменений.

База пилота после проверок содержит ноль пользователей, записей, заданий и заметок. Проверочные проекты остановлены. Их тома и синтетический оригинал сохранены отдельно. Запущенных тестовых отправителей нет.

Согласованные копии пилота и mock-проекта включают состояние удалённого бота. Обе копии восстановлены в новых проектах без приложения, worker, scheduler и Telegram. В mock-восстановлении проверены один оригинал аудио, две заметки и одно напоминание. Выключенный бот не включался при резервировании.

Ежедневный таймер копий включён на 04:00 Москвы с задержкой до двух минут. Архивы не удаляются автоматически. Копии пилота, mock-проекта и служебной конфигурации скачаны на ПК, SHA-256 совпали. Отдельная копия конфигурации расшифрована на ПК без вывода секретов.

На ПК используется каталог `Береста\Beresta-recovery`. В нём находятся `recovery.key` и подпапки копий `backups\pilot`, `backups\mock`, `backups\config`. Ключ age хранится только на ПК. При проверке восстановления он передавался через SSH stdin и не сохранялся на диске VPS. Приватный SSH-ключ ПК на серверы не передавался.

## Что осталось владельцу

1. Зарегистрировать домен и создать A-запись выбранного имени на `178.217.98.101`. Для `app.<домен>` имя DNS-записи равно `app`. Для корня домена использовать `@`. AAAA пока не создавать. Хельсинки DNS не требует.
2. Заполнить Telegram-токен и Cloud.ru key скрытым вводом через `Beresta-Secrets.cmd` в папке «Береста». Этот файл не запускает службы и не обращается к Cloud.ru.
3. Настроить домен, открыть и затем закрыть регистрацию, запустить один экземпляр бота и лично включить worker для первого текста. Точный порядок находится в [server-deploy-v1.md](server-deploy-v1.md#домен-и-первое-пользовательское-испытание). Общий и пользовательский лимиты сейчас равны 1.
4. Сохранить копию `recovery.key` на отдельном защищённом носителе. Скачать следующие ежедневные копии через `Beresta-Backups.cmd`. Постоянный перенос копий с VPS и внешние уведомления об отказах пока не настроены.
5. До голосового пользовательского теста подтвердить протокол и модель STT программного шлюза. Кандидат адаптера остаётся выключенным. Автоматическое распознавание, настоящий Cloud.ru и реальная доставка Telegram агентом не проверялись.

Иногда прямой SSH к РФ зависает. Рабочий доступ проверен через Хельсинки и WireGuard с `HostKeyAlias=178.217.98.101`. Пересылка ssh-agent выключена. Windows-файлы запуска используют этот путь.
