# Дневной лимит ИИ

## Как это работает

У каждого человека на день есть 30 единиц. Запись, которую отправили в ИИ, тратит единицы сразу при сохранении.

| Запись | Цена |
| --- | --- |
| Текст | 1 |
| Голос | 2 и ещё 1 за каждую полную минуту |

Примеры для голоса. 0:40 стоит 2. 1:30 стоит 3. 3:00 стоит 5.

Сутки считаются по календарному дню в Москве, с 00:00 до 00:00. Утром счёт начинается заново.

Когда новая запись не помещается в остаток, она не теряется. Исходник сохраняется как обычная запись без ИИ (`processing_mode` равен `manual`), задание не создаётся, единицы не тратятся. Веб и бот прямо говорят об этом: «Лимит ИИ на сегодня исчерпан. Запись сохранена без ИИ, разобрать её можно завтра.» Голос попадает в список как заметка «Голосовая запись без ИИ». Оригинал можно послушать, расшифровку можно вписать вручную.

Записи, которые человек сам сохранил без ИИ, единиц не тратят.

## Что видит человек

В вебе под выбором обработки всегда есть тихая строка «ИИ на сегодня: осталось 27 из 30». Под ней мелко написаны цены: «Текст 1, голос 2 + 1 за минуту». Когда остаётся 3 или меньше, строка становится тёплого цвета. Строка обновляется после каждого сохранения и после завершения задания. Если дневной лимит выключен (`NOTES_DAILY_UNIT_LIMIT=0`), строки нет.

Когда остаток равен 0, или запись только что сохранилась без ИИ из-за лимита, строка заменяется заметкой «Лимит ИИ на сегодня исчерпан. Обновится через 5 ч 12 мин. Записи сохраняются без ИИ.» Время считается от `limit_resets_at` и обновляется раз в 30 секунд (форматы «5 ч 12 мин», «40 мин», «меньше минуты»). Скринридер читает только первую фразу, а не каждое обновление времени. Пункт «Структурировать с ИИ» отключён, выбрано «Сохранить без ИИ». Когда время выйдет, страница сама спросит `GET /api/v1/provider/usage` и вернёт ИИ. Таймер один, при выходе из аккаунта он останавливается.

Старый предел за всё время (`user_remaining` или `global_remaining` равны 0) показывается как раньше, баннером «Лимит ИИ исчерпан. Сохранение без ИИ доступно.» Таймера для него нет, он не обновляется.

В боте обычный ответ при остатке 5 и меньше получает вторую строку «ИИ на сегодня: осталось N.» Когда запись сохранена без ИИ, бот пишет «Лимит ИИ на сегодня исчерпан. Запись сохранена без ИИ. Лимит обновится через 5 ч 12 мин.» Если ядро не прислало время, остаётся прежний текст про «завтра». «❓ Помощь» коротко рассказывает про лимит и цены.

## Что не изменилось

Дневной лимит стоит поверх старых. Общий предел `NOTES_LIVE_CALL_LIMIT`, пауза worker при его исчерпании и предел на человека за всё время `NOTES_LIVE_USER_CALL_LIMIT` работают как раньше. Дневные единицы не равны вызовам к Cloud.ru. Одна голосовая запись по-прежнему занимает два общих слота, один на распознавание и один на текст (см. [voice-text-replies-v1.md](voice-text-replies-v1.md)), а одна текстовая занимает один слот.

## Настройки

Все числа задаются в `.env.production`, менять код не нужно.

| Переменная | По умолчанию | Смысл |
| --- | --- | --- |
| `NOTES_DAILY_UNIT_LIMIT` | 30 | Единиц на человека в день. 0 отключает дневную проверку |
| `NOTES_TEXT_UNIT_COST` | 1 | Цена текста |
| `NOTES_AUDIO_UNIT_BASE` | 2 | Цена любого голоса |
| `NOTES_AUDIO_UNIT_PER_MINUTE` | 1 | Добавка за каждую полную минуту голоса |
| `NOTES_LIMIT_TIMEZONE` | Europe/Moscow | Часовой пояс, по которому считаются сутки |

Неверное число или неизвестный пояс остановят запуск с понятной ошибкой.

## Как поменять на сервере

1. Изменить нужные строки в `.env.production`.
2. Пересоздать сервисы, лимит проверяет API.

```
beresta-core up -d --no-deps --force-recreate api
```

Worker читает те же переменные, но на лимит не влияет. Если хочется держать окружение одинаковым, пересоздайте его тоже, но только когда очередь пуста и по правилам из [voice-text-replies-v1.md](voice-text-replies-v1.md).

```
beresta-core --profile owner-live up -d --no-deps --force-recreate worker
```

Новые числа действуют сразу для всех записей текущих суток, потому что остаток считается заново из сохранённых записей.

## Для веба

`GET /api/v1/provider/usage` сохранил прежние поля и получил новые.

| Поле | Смысл |
| --- | --- |
| `daily_unit_limit` | Лимит на день, 0 значит без дневной проверки |
| `daily_units_used` | Потрачено сегодня |
| `daily_units_remaining` | Осталось. Для лимита 0 равно `null` |
| `text_unit_cost`, `audio_unit_base`, `audio_unit_per_minute` | Текущие цены |
| `limit_resets_at` | Ближайшая полночь в формате ISO, например `2026-10-10T00:00:00+03:00` |

Ответ на сохранение записи, не поместившейся в лимит, имеет тот же вид, что и у записи без ИИ, плюс `ai_limit_exceeded: true`. Для текста это `capture_id`, `job_id: null`, `status: saved`, `note_id`. Для голоса в вебе добавляются и обычные поля задания, но `id` равен `null`. В ответе внутреннего API для Telegram поле `ai_limit_exceeded` есть у текста всегда, у голоса только при `true`. Запись, которая не упёрлась в лимит, поля не имеет (веб) или имеет `false` (Telegram, текст).

Ответы `/internal/v1/telegram/updates` и `/internal/v1/telegram/voice` получили два необязательных поля, посчитанных после сохранения записи теми же функциями из `app/limits.py`.

| Поле | Смысл |
| --- | --- |
| `ai_units_remaining` | Сколько единиц осталось на сегодня, целое число. `null`, если дневной лимит выключен |
| `ai_limit_resets_at` | Ближайшая полночь в формате ISO с поясом. `null`, если дневной лимит выключен |

Повтор того же update возвращает сохранённый ответ, поэтому остаток в нём может устареть. Адаптер такие ответы принимает, лишние ключи ему не мешают.

## Технические детали

Остаток не хранится в отдельном счётчике. Он считается как сумма цен записей человека за сегодня с `processing_mode = ai`, по `input_kind` и `audio_seconds`. Миграции нет, счёт не может разойтись с записями.

Проверка идёт под той же блокировкой аккаунта, что и проверка очереди. Две одновременные записи одного человека выстраиваются по очереди, поэтому превысить лимит они не могут. Если блокировку когда-нибудь уберут, запас ошибки будет не больше одной записи.

Если очередь заданий человека полна, а дневной лимит исчерпан, запись сохранится без ИИ. Если очередь полна, а лимит есть, ответ остаётся 429, как раньше. Проверка очереди для голоса идёт до сохранения файла и дневной лимит не учитывает, поэтому при полной очереди голос получит 429 и в этом случае.

Повтор того же запроса с тем же `Idempotency-Key` возвращает тот же ответ с тем же признаком, а не 409. Признак хранится в событии `capture_saved` (`outcome = ai_limit`).

Единицы на человека по дням в админке пока не выводятся. Их можно получить запросом к `captures` с теми же условиями, что в `app/limits.py`.

## Что не проверено

Живой Cloud.ru не вызывался. Проверки сделаны на mock-провайдере и подменённом транспорте.
