# Безопасность админки

Админ больше не обычный пользователь с правами. У него свой логин, пароль и
код из приложения-аутентификатора. Открыть админку можно только из приватной сети.

## Что изменилось

- Таблицы `admin_accounts`, `admin_sessions` и `admin_audit_log`. Миграция `a7c1e2d3f4b5`.
- Миграция переводит всех `users.role = 'admin'` в `user`. Колонка осталась, но ничего не читает её.
  Команда `python -m app.admin` и проверки роли удалены.
- Вход по логину, паролю и коду TOTP (RFC 6238, SHA1, 6 цифр, шаг 30 секунд, окно плюс минус один шаг).
  Один и тот же код второй раз не принимается.
- Любая ошибка входа даёт одно и то же сообщение. После 5 неудач аккаунт блокируется на 15 минут.
- Сессия живёт 8 часов, без действий 30 минут. Cookie `beresta_admin` с HttpOnly и SameSite=Strict.
  Запросы, которые что-то меняют, требуют заголовок `X-CSRF-Token`.
- Админка живёт на новом префиксе `/admin-api/v1/`. Старые `/api/admin/*` удалены,
  обычная сессия до админки не дотянется.
- Вне разрешённых сетей `/admin*`, `/static/admin.*` и `/admin-api/*` отвечают 404.
  Запросы с заголовками прокси (`X-Forwarded-For` и похожими) тоже получают 404.
  Публичный Caddy дополнительно отвечает 404 на эти пути.
- Журнал действий в базе и на странице «Журнал действий», последние 100 записей.
  Туда попадают вход и неудачный вход, блокировка, выход, выгрузки, смена статуса обращения,
  действия из консоли. Паролей, кодов и текстов пользователей там нет.
- Метрики для организаторов только архивом ZIP из админки. Публичного API-токена нет.

## Первый администратор

На сервере ядра.

```sh
beresta-core run --rm api python -m app.admin_cli create andrey
beresta-core run --rm api python -m app.admin_cli confirm andrey 123456
```

Первая команда дважды спросит пароль (не короче 12 символов), покажет ссылку `otpauth://`
и секрет base32. Они показываются один раз. Добавьте их в приложение-аутентификатор.
Вторая команда включает вход, когда вы передали текущий код из приложения.

Остальные команды.

```sh
beresta-core run --rm api python -m app.admin_cli list
beresta-core run --rm api python -m app.admin_cli disable andrey
beresta-core run --rm api python -m app.admin_cli enable andrey
beresta-core run --rm api python -m app.admin_cli reset-2fa andrey
```

`reset-2fa` выдаёт новый секрет, закрывает сессии и требует нового `confirm`.
`disable` закрывает сессии и запрещает вход. `enable` снимает блокировку после неудачных попыток.

## Как открыть админку

Через WireGuard откройте `http://10.77.0.1:18000/admin`, если ваш компьютер в сети `10.77.0.0/24`.

Через SSH-туннель.

```sh
ssh -L 18000:10.77.0.1:18000 <пользователь>@<сервер>
```

Затем откройте `http://127.0.0.1:18000/admin`.

Админка работает по обычному HTTP внутри приватной сети, поэтому в `.env.production` нужно поставить

```
NOTES_ADMIN_COOKIE_SECURE=false
```

и пересоздать API командой `beresta-core up -d api`. По умолчанию cookie помечается как Secure
и без HTTPS браузер её не сохранит. Все остальные настройки cookie остаются строгими.

Разрешённые сети задаёт `NOTES_ADMIN_ALLOWED_NETWORKS`. По умолчанию это
`127.0.0.1/32,::1/128,10.77.0.0/24`. Адрес берётся из соединения с API.
Если через туннель приходит 404, посмотрите адрес Docker-шлюза сети проекта
и добавьте его в список, например `172.18.0.1/32`. Сети `0.0.0.0/0` и `::/0` приложение не принимает.

Сам порт `18000` слушает только адрес WireGuard (`deploy/compose.core-private.yaml`).
Это первая преграда, а проверка адреса в приложении вторая.

## Выгрузка метрик для организаторов

В админке откройте «Архив метрик», выберите даты (не больше 92 дней, дни по Москве) и нажмите
«Скачать архив метрик». Внутри ZIP

- `README.txt` с определениями (реальный пользователь, DAU, исключения, псевдонимы),
- `daily.csv`, `users.csv`, `events.csv`, `ai_calls.csv`, `errors.csv`, `errors_by_day.csv`.

Имён пользователей, текстов записей и контактов в архиве нет. Идентификаторы заменены псевдонимами
на основе `NOTES_ANALYTICS_PSEUDONYM_KEY_FILE`. Пока ключ не меняют, один человек
получает один и тот же псевдоним во всех выгрузках. Если ключ не задан,
псевдонимы действуют только до перезапуска API, и архив скажет об этом в README.
Тестовые аккаунты исключены. Каждая выгрузка записывается в журнал.

Правила расчёта.

- Реальный пользователь выполнил хотя бы один целевой сценарий (с ИИ или без) по всей истории до конца периода.
- DAU считает уникальных реальных пользователей с активным действием в календарный день по Москве.
- Записи, вызовы ИИ и ошибки считаются по всем нетестовым аккаунтам.

## Аккаунты команды как тестовые

```sh
beresta-core run --rm api python -m app.admin_cli mark-test-user mark
beresta-core run --rm api python -m app.admin_cli unmark-test-user mark
```

Помеченный аккаунт исключается из статистики и архива за всю историю, в том числе за прошлые дни.
Новые события такого аккаунта сразу сохраняются как тестовые. Пометьте всех троих членов команды
до выгрузки для организаторов.

## Что нужно знать

- Секрет TOTP хранится в базе открытым текстом и ни одним методом API не возвращается.
  Шифрование ключом приложения можно добавить отдельно.
- Блокировка по 5 неудачам работает на аккаунт, поэтому чужой человек в приватной сети
  способен временно запереть вход. Снимает блокировку команда `enable`.
- Обычные пользователи и пользователи с прежней ролью admin не получают ничего.
  Из сети пользователя админка вообще не существует (404).
