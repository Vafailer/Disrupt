создана от `90b4dd58f350ea4f02f7aff56c5ea4add3934ffc`.

## Что прошло локально

- Python 3.12. Зависимости установлены из существующего requirements.txt.
- `python -m ruff check app tests migrations scripts` прошёл.
- `node --check app/static/app.js` прошёл. Это проверка синтаксиса JavaScript.
- `python -m pytest -q` завершился с **85 passed, 2 skipped**.
  Доступ к сети для моделей был запрещён.
- На пустой SQLite выполнены `alembic upgrade head` и `alembic check`.
  Расхождений нет.
- На старой заполненной SQLite выполнены upgrade, проверка аккаунта, сессии,
  оригинала, версии и ревизии, затем downgrade, foreign_key_check и повторный
  upgrade. Итоговый alembic check не нашёл расхождений.
- Для PostgreSQL прошла генерация `alembic upgrade head --sql`.
  Фактического подключения к PostgreSQL не было.
- OpenAPI воспроизводится командой `python -m scripts.export_contract`.
  Все локальные $ref разрешаются. Будущие методы помечены contract-only.
  Пример JSON админки и значения процентов проверены по схеме.
- `git diff --check` прошёл. Работа выполнена в отдельной ветке.
  Main и файлы второго разработчика не менялись.

Тесты проверяют точное сохранение текста, ручной режим без Job, CSRF,
доступ к чужим данным, одноразовый код и его срок, подтверждение и конфликт
привязки, сервисный секрет, int64, строгие поля и лимиты.

Также проверены общий update ID для разных операций, четыре одновременных
повтора, откат Inbox, Capture, Job и события при сбое, конкурентная квота очереди,
роль admin и защита прямого доступа к статике.
Аналитическая сессия отделена от сессии входа. Повторы событий не создают копий,
фоновая обработка не продлевает сессию пользователя.

## Что осталось проверить

Два теста PostgreSQL пропущены, потому что TEST_POSTGRES_URL не задан.
Запустить локальный сервер в доступной среде не удалось.
Генерация SQL эти тесты не заменяет. В CI репозитория настроен PostgreSQL service.
Там должны пройти обычный тест PostgreSQL и добавленный тест привязки,
конкурентного Inbox и ручного сохранения. Результат CI нужно проверить
после публикации ветки.

SOCKS proxy в среде мешал старому тесту запрета транспорта при создании httpx client.
Для тестового процесса убраны ALL_PROXY, all_proxy, HTTP_PROXY, HTTPS_PROXY,
http_proxy и https_proxy. Сетевые запреты autouse-фикстуры оставались включены.
Cloud.ru не вызывался. Ключ не искался, не читался и не менялся.
Осталось существующее предупреждение StarletteDeprecationWarning о TestClient/httpx.

Ещё не проверены настоящий бот на staging, настоящая модель и STT, расходы,
полная аналитика и CSV, напоминания и scheduler, внешний вид в браузере,
mock-нагрузка при 1/5/10 RPS, HTTPS, резервное копирование и восстановление.
Приёмка 30 текстов, 20 аудио, 30 напоминаний и 5 внешних пользователей тоже впереди.
