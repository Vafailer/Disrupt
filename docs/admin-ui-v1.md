# Экран бизнес-статистики

Ветка codex/admin-ui-v1 создана от feature/reminder-delivery-v1, SHA 73f47d54d290fe004958fa7eb1d83c039d6e4902. Рабочие ветки и main не объединялись. Scheduler и доставка уже реализованы Марком, повторной реализации в этой ветке нет.

## Что работает

Добавлены app/static/admin.html, admin.js и admin.css. Маршрут /admin отдаёт экран. С версии admin-security-v1 экран показывает вход (логин, пароль, код) и работает только из приватной сети, см. [admin-security-v1.md](admin-security-v1.md). Роль users.role больше не используется.

Экран запрашивает GET /admin-api/v1/summary с from/to/channel/source и usage_limit=50/usage_offset. Даты считаются по Москве. По умолчанию выбраны семь завершённых дней. DAU подписан датой последнего завершённого дня среза; для текущего дня явно указан предварительный результат.

Показаны пользователи и активация, дневные показатели, воронка, D1/D7 и ожидающие когорты, стоимость и известный подытог, токены, сессии, качество обработки/доставки, операции с псевдонимами. Числа и доли берутся из серверного ответа, клиент не рассчитывает бизнес-агрегаты. Неполный или некорректный ответ не показывается частично. null выводится как «Нет данных», ноль остаётся нулём.

Пагинация следует X-Next-Usage-Offset; карточки относятся ко всему периоду, не к странице usage. CSV скачивается через GET /admin-api/v1/export с теми же фильтрами без pagination. Клиент не собирает CSV из текущей страницы. Возвращённый MIME должен быть text/csv. Сервер отвечает за полный срез, защиту от CSV-формул и no-store по общему контракту.

При смене фильтра прежние цифры скрываются; запоздалый ответ не может перезаписать новый срез. Для запросов заданы timeout, no-store и same-origin credentials. После 401/403 данные убираются. Строки API вставляются через textContent, а не HTML. Личных записей, аудио, контактов и сохранения статистики в localStorage нет.

## Что пока не готово

В основании этой ветки API summary/export всё ещё contract-only. Их расчёт и реализация остаются за Марком. Поэтому на настоящем /admin сейчас появится честное сообщение «API статистики ещё не подключён», а не фиктивные показатели. Пример admin-summary.json используется только в тестах.

После подключения API нужно сверить JSON и CSV с эталонной выборкой, объединение каналов в одного пользователя, исключение тестовых аккаунтов, московские границы дней, созревание когорт, неизвестный usage и фактическую роль. Успех DOM-тестов не подтверждает правильность серверных расчётов.

## Проверки

```sh
python -m pytest -q
python -m ruff check app tests migrations scripts telegram_adapter
node --check app/static/admin.js
NODE_PATH=/path/to/jsdom/node_modules node tests/web_admin.cjs
```

CI использует уже закреплённый jsdom@26.0.0. DOM-тесты проверяют фильтры, null/zero, D7 без созревшей когорты, пагинацию без изменения агрегатов, CSV, 401/403/404/503, XSS, повреждённый ответ и гонку запросов. Python-тест проверяет доступ к HTML/JS/CSS и отзыв роли.

Общие API, расчёты, модели, миграции и основной веб не изменены. Из существующих тестов скорректировано ожидание /admin: вместо отсутствующего файла теперь проверяется доступный экран. В CI добавлен отдельный запуск DOM-теста админки.
