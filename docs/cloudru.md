# Подключение Cloud.ru

Приложение отправляет текст в модели Cloud.ru через OpenAI-совместимый шлюз программы Sber500. В инструкции команде указан Base URL `https://shared1.multitool.works:4000/v1`. Код проверен с вымышленным ключом и подменёнными HTTP-ответами. Выданный команде токен при разработке не использовался, поэтому доступность шлюза и качество ответа ещё не подтверждены.

У Cloud.ru есть [каталог моделей](https://cloud.ru/docs/foundation-models/ug/topics/overview__available__models), но набор моделей на шлюзе программы может отличаться. Организаторы рекомендуют получать актуальный список через `GET /v1/models` с выданным ключом. Агент этот запрос не выполняет.

## Локальная проверка владельцем

На Windows откройте `start-cloudru.cmd`. Скрипт попросит ключ скрытым вводом, ID модели и максимальное число запросов. По умолчанию он предложит `deepseek-v4-flash` из сообщения организаторов. Это предположение, доступность модели с вашим ключом пока не проверена. Лимит по умолчанию равен `5`. Данные хранятся отдельно от демо в `data/cloudru.db`.

Ключ живёт в окружении запущенного процесса и не записывается в `.env` или базу. Во время работы процесс и локальные инструменты с нужными правами могут получить к нему доступ. Для сервера используйте штатное хранение секретов, описанное в [развёртывании](deployment.md). Ключ не нужно отправлять нам в чат.

Запуск скрипта не проверяет ключ и не запрашивает список моделей. Обращение к модели начинается после отправки записи. При `401` или `403` проверьте ключ и адрес шлюза. При `404` проверьте ID модели. При `429` уточните лимит у организаторов. Ключ и текст записи не присылайте в общий чат.

Для первой проверки в новой базе хватит лимита `1`. Если `data/cloudru.db` уже использовалась, предел должен быть больше числа занятых слотов. Откройте `http://127.0.0.1:8000` и отправьте одну короткую запись. Если задание завершилось и появилась заметка, значит запрос прошёл через настоящий Cloud.ru. Надпись «Режим Cloud.ru» сама по себе подтверждает только настройку приложения.

После ошибки откройте «Последние записи», посмотрите код ошибки и `data/errors.log`. Для разбора достаточно кода, `http_status` и ID модели. Повторная отправка займёт ещё один слот; если он нужен, при следующем запуске можно увеличить общий лимит для той же базы.

## Настройки сервера

`.env.example` показывает имена переменных, но Python не загружает этот файл автоматически. Для отдельного worker нужны следующие настройки окружения:

| Переменная | Что указать |
| --- | --- |
| `NOTES_PROVIDER` | `cloudru` |
| `NOTES_ALLOW_LIVE_REQUESTS` | `true` для явного включения обращений |
| `NOTES_CLOUDRU_MODEL` | ID доступной текстовой модели |
| `NOTES_CLOUDRU_BASE_URL` | `https://shared1.multitool.works:4000/v1` для ключа программы |
| `NOTES_CLOUDRU_API_KEY` | Секрет только для worker; на сервере он читается из secret-файла |
| `NOTES_LIVE_CALL_LIMIT` | Общий предел обращений для этой базы |
| `NOTES_LIVE_USER_CALL_LIMIT` | Предел обращений одного пользователя |

До пользовательского запуска также нужны HTTPS, резервные копии, закрытая регистрация после создания аккаунтов и верные `NOTES_PUBLIC_ORIGIN` с `NOTES_SECURE_COOKIES=true`. Локальный `start-demo.cmd` и обычный Docker Compose всегда используют `mock`.

## Как считается расход

На новую запись приходится один запрос к модели. Адаптер отправляет POST на `https://shared1.multitool.works:4000/v1/chat/completions` с Bearer-ключом и запрашивает JSON-ответ. Вход ограничен 12 000 символов, ответ ограничен `max_tokens=4000`. Автоматического повтора после тайм-аута или ошибки нет.

Слот в лимите резервируется до отправки. Если связь оборвалась, мы не знаем, обработал ли Cloud.ru запрос, поэтому слот не возвращается. Это защита от незаметных повторных расходов. Лимит считает обращения. Цена же зависит от модели и фактического числа токенов.

При ошибке исходная запись остаётся в задании. Повтор HTTP-запроса с прежним `Idempotency-Key` вернёт то же задание без нового обращения. Новый ключ создаст новую запись и может занять ещё один слот. Если результат неясен, сначала откройте прежнее задание.

Режим провайдера записывается в задание при его создании. `mock`-worker не забирает задания Cloud.ru и наоборот. Для демо и пользовательского пилота используйте разные базы, не переключайте режим при незавершённых заданиях.

## Что оценить на настоящей модели

Начните с короткого текста и посмотрите, сохранила ли модель смысл и сомнения автора. Затем проверьте, не добавила ли она фактов от себя, помогает ли разметка и действительно ли выводы следуют из исходника. Код проверяет формат и опорный фрагмент, но полезность ответа может оценить только человек.

Распознавания речи в этой версии нет. Доступ к текстовой модели сам по себе не подтверждает доступ к Audio-to-Text.
