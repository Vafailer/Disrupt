# Установка безопасности и админки

База PR #33, `47897b8`, вручную объединена с установленным `3094ece`.
Исправления сохранения расшифровки и автосохранения оставлены вместе с тестами.
Main и ветка Андрея не меняются.

Админка доступна через SSH-туннель на `http://127.0.0.1:18000/admin`.
Публичный Caddy закрывает её и внутренний API. Разрешён только точный адрес
шлюза Docker дополнительно к приватным сетям. Cookie админки внутри туннеля
работает с `NOTES_ADMIN_COOKIE_SECURE=false`.

`scripts/setup-admin.cmd` создаёт администратора `mark`. Пароль вводится
скрыто, два раза. Секрет аутентификатора сохраняется в закрытой папке
`Beresta-owner-secrets` на ПК, сверяется с временной серверной копией,
после чего временная копия удаляется. Скрипт открывает файл владельцу и
просит код из аутентификатора. Следующий вход требует нового кода.
Если подтверждение не прошло, `setup-admin.cmd -ConfirmOnly` повторяет только
ввод кода. Существующий аккаунт и сохранённый секрет не перезаписываются.
`scripts/open-admin.cmd` открывает страницу и держит SSH-туннель до Enter.
Ни один скрипт не читает приватный SSH-ключ и не передаёт пароль в аргументах.

Для Андрея нужен отдельный администратор и отдельный секрет TOTP.
Не передавайте ему ключ шифрования данных или приватный SSH-ключ Марка.
Для собственного туннеля Андрей передаёт публичную часть своего SSH-ключа.

Ключ данных создаётся один раз. На ядре он имеет права 0400 и владельца 1000.
Отдельная копия на ПК сверяется до включения шифрования. Ключ не попадает
на сервер бота, в Git или архив базы и аудио. Резервные копии до установки
сохраняются до успешного восстановления новой копии.

После шифрования хеш аудиофайла на диске отличается от хеша оригинала в БД.
Поэтому восстановление принимает `--data-key-file` и `--audio-verifier-image`.
Проверка выполняется в контейнере без сети с томом аудио только для чтения.
Она расшифровывает оригинал в памяти и сверяет его SHA-256. API, worker,
scheduler и Telegram там не запускаются. Ключ не извлекается из архива.
Старые копии без шифрования продолжают проверяться без этих аргументов.

Полная сборка использует зависимости из requirements.txt. Для Debian
используются HTTPS и IPv4, поскольку загрузка пакетов по HTTP на VPS отказала.
Runtime-reuse для этой версии не применяется.

Для почты выбран Яндекс 360. Отправка останется выключенной до создания
ящика, сохранения пароля приложения и подтверждения доставки владельцем.
В PR #33 есть привязка email и восстановление по ссылке, но регистрации
по email с кодом нет. Её нельзя считать выполненной настройкой SMTP.

## Результат 10 октября

На обоих VPS установлен `0462a10e0b262da195c678bebc9340c5cd85965c`.
Схема `c9e4a1b2d3f6`, все пять служб ядра и один адаптер работают.
Реальный worker и STT остаются включёнными, лимиты 1000/100 сохранены.
Регистрация по логину бессрочная. Почта выключена.

До установки прошли 1008 тестов в контейнере без сети, 11 пропущены.
CI с PostgreSQL, контрактом, DOM и образами зелёный. CI резервирования
с зашифрованным аудио и отдельным сервером бота тоже зелёный.
После исправления передачи stdin ещё 38 затронутых тестов прошли локально.

Миграции и шифрование проверены на свежем изолированном восстановлении.
Затем на остановленном ядре записаны контрольные хеши 20 старых таблиц.
После миграций и шифрования они совпали. В шифруемых столбцах и аудио
`plain=0`, `old=0`. Копия ключа данных на ПК сверена, значение не выводилось.

Новая согласованная копия `beresta-20261010T193046-eab46d0a.tar.age` скачана
на ПК. SHA-256 `b16846cd0658fbf251eb12482930efa003a4deafc7e50564dab0a47bbde2a82f`.
Штатное изолированное восстановление проверило четыре аудио и все 20 старых
таблиц после расшифровки. Приложения и отправитель не запускались, БД остановлена.
Предыдущие архивы и все тома сохранены.

Из контейнера бота проверены VPN, health, 401 без и с неверным секретом,
422 на неверном теле с правильным секретом, публичные 404 для внутренних
и административных путей, HTTPS 200, отсутствие публичного HTTP на 18000.
PostgreSQL не опубликован. Приватные `/admin` и `/static/admin.js` дают 200,
`/admin-api/v1/me` без сессии даёт 401. Прокси-заголовок даёт 404.

Администраторов пока нет. Владелец выполняет скрытый ввод пароля и импорт
секрета в аутентификатор через setup-admin.cmd. Живой вход с телефона
агент не подтвердил. Оператор и контакт в политике ещё не заполнены владельцем.
