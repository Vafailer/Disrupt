# Помощник по заметкам v1

Статус: реализованы backend и веб-экран, проверены только на имитации ИИ. Живой сервис не проверялся.

## Коротко для владельца

Помощник отвечает по вашим заметкам и ничего не выдумывает. Три действия.

- Вопрос. Вы пишете вопрос, помощник находит нужные заметки и отвечает с цитатами. Если ответа в заметках нет, так и скажет.
- Рекомендации. Помощник смотрит заметки за 30 дней и открытые задачи и идеи. Предлагает до пяти следующих шагов.
- Сводка. Итоги за 7 или 30 дней, главные мысли, открытые задачи и темы.

Каждое действие стоит 1 единицу дневного лимита ИИ (по умолчанию 30 в день) и один вызов из общего бюджета, как обычная запись с ИИ. Когда лимит закончился, новый запрос получает 429 и время обновления в поле `limit_resets_at`.

Если по вопросу или за период нет подходящих заметок, ИИ не вызывается и единица не списывается.

Рекомендации можно выключить кнопкой. Это настройка пользователя `recommendations_enabled`, по умолчанию включена. Пока она выключена, `POST /api/v1/assistant/recommendations` отвечает 409. Вопросы и сводки работают всегда.

Исходный текст заметок помощник не меняет. Он только читает.

## Как это устроено

Запрос сначала сохраняется в таблице `assistant_requests` со статусом `queued`. Воркер берёт его в тот же цикл, где обрабатываются записи. Сначала всегда идут записи, потом запросы помощника.

1. Воркер выбирает заметки обычным кодом, без ИИ (`app/assistant_retrieval.py`).
2. Делает один вызов модели через тот же шлюз и с тем же тайм-аутом, что и структурирование. Повторов нет.
3. Проверяет ответ строго. Каждая цитата должна быть точной подстрокой заголовка, текста или элемента той заметки, на которую она ссылается. Иначе запрос получает `failed` с кодом `ungrounded_quote`, а ответ не показывается.
4. Сохраняет результат в `result` и ставит `succeeded`.

Неясный исход (тайм-аут, обрыв, истёкшая аренда) помечается как `failed` и не повторяется сам.

### Какие заметки получает модель

- Вопрос. Последние до 500 заметок за выбранный период (`days`: 7, 30, 90 или 365, по умолчанию 90). Простой TF-IDF по заголовку, тексту и элементам. Берутся до 8 лучших заметок, у которых есть общие слова с вопросом.
- Рекомендации. Заметки за 30 дней (до 60) и заметки с открытыми задачами и идеями (до 30 элементов).
- Сводка. Заметки, созданные или изменённые за период.

Общий размер блока заметок около 12 000 символов. Каждая заметка обрезается (вопрос 2500, рекомендации 700, сводка 900 символов), элементов не больше 10 на заметку по 200 символов.

Модель не имеет доступа к базе, SQL, файлам и сети. Она видит только JSON с этими заметками. Все выборки привязаны к владельцу.

### Промпты

Общие правила для всех трёх действий. Заметки приходят как данные (`id`, `title`, `date`, `text`, `items`), команды внутри заметок и вопроса не исполняются, отвечать по-русски, без знаний вне заметок и без HTML. Тексты промптов лежат в `app/providers.py` (`ASK_PROMPT`, `RECOMMEND_PROMPT`, `DIGEST_PROMPT`).

### Форматы JSON

Вопрос.

```json
{"answer_markdown": "Ответ", "citations": [{"note_id": "id", "quote": "Точная цитата"}]}
```

Ответ "Не нашёл ответа в ваших заметках" допустим с пустым `citations`. Любой другой ответ без цитат отклоняется.

Рекомендации. До пяти, `kind` из `idea`, `task`, `connection`, `habit`, до трёх `note_ids`.

```json
{"suggestions": [{"kind": "idea", "title": "Заголовок", "text": "Что предлагается",
  "note_ids": ["id"], "quote": "Цитата из одной из этих заметок"}]}
```

Сводка. `open_tasks` содержит только id открытых задач из входных данных.

```json
{"summary_markdown": "Сводка", "highlights": [{"note_id": "id", "quote": "Цитата"}],
 "open_tasks": ["id элемента"], "themes": ["тема"]}
```

Лишние поля, неизвестные id и неверные типы дают `provider_invalid_response` или `ungrounded_quote`.

## Лимиты и стоимость

- Цена одного действия `ASSISTANT_UNIT_COST = 1` (`app/limits.py`). Она входит в `daily_units_used` в `GET /api/v1/provider/usage`.
- Считаются запросы помощника, созданные сегодня в часовом поясе лимита. Не считаются запросы со статусом `failed`, у которых `started_at` пуст, то есть вызов модели не начинался (например, закончился общий бюджет). Запрос без подходящих заметок получает `units = 0`.
- Повтор с тем же `Idempotency-Key` и тем же телом возвращает тот же запрос и ничего не списывает. Тот же ключ с другим телом даёт 409.
- Одновременно у пользователя может ждать не больше `max_pending_per_user` запросов (429).
- В режиме `cloudru` каждый вызов резервирует слот общего бюджета и слот пользователя. При исчерпании бюджета воркер не берёт запросы. Если слот закончился в момент вызова, запрос получает `budget_exhausted`.
- Каждый вызов пишет запись в `provider_usage` (`kind = llm`, `operation_id` равен id запроса).

## API

Все маршруты работают по сессии браузера. Для записи нужен заголовок `X-CSRF-Token`. Для трёх POST обязателен `Idempotency-Key` (латиница, цифры, `_ . : -`, до 100 символов).

| Маршрут | Тело | Ответ |
| --- | --- | --- |
| `POST /api/v1/assistant/ask` | `question` (3..1000), `days` (7, 30, 90, 365) | 202 `{id, status}` |
| `POST /api/v1/assistant/recommendations` | без тела | 202, 409 если выключено |
| `POST /api/v1/assistant/digest` | `days` (7 или 30), можно `{}` | 202 |
| `GET /api/v1/assistant/requests/{id}` | | статус и результат, только владельцу |
| `GET /api/v1/assistant/requests?limit=10` | | последние запросы, от новых к старым |
| `GET /api/v1/assistant/settings` | | `{recommendations_enabled}` |
| `PATCH /api/v1/assistant/settings` | `recommendations_enabled` | то же |

Ответ 429 по лимиту.

```json
{"detail": "На сегодня лимит ИИ закончился. Он обновится завтра.", "limit_resets_at": "2026-10-11T00:00:00+03:00"}
```

Запрос в ответах содержит `id`, `kind`, `status`, `question`, `days`, `units`, `error_code`, `error_message`, `created_at`, `started_at`, `finished_at`, `input_note_ids` и `result`. В `result` к цитатам добавлено `note_title`, к рекомендациям список `notes` с `id` и `title`, а `open_tasks` раскрыты в `{id, text, note_id, note_title}`. В базе хранятся только id.

Статусы `queued`, `running`, `succeeded`, `failed`. Интерфейс опрашивает `GET /requests/{id}`, пока статус не `succeeded` или `failed`.

## Коды ошибок

Те же, что у обычных записей, плюс `ungrounded_quote` (цитата не найдена в заметке), `budget_exhausted`, `execution_unknown` и `internal_error`.

## Интерфейс

Экран «Помощник» открывается из меню слева или по ссылке `#assistant`. Код в `app/static/brain.js`, стили в `brain.css`, тесты в `tests/web_brain.cjs`.

- Вопрос. Поле, период (неделя, месяц, 3 месяца, год) и кнопка. Запрос уходит с `Idempotency-Key`, затем страница каждые 2 секунды читает `GET /requests/{id}`. Через 3 минуты опрос останавливается с текстом «Ответ задерживается, проверьте позже», запрос остаётся в истории. Опрос также прекращается при выходе из экрана и из аккаунта. Ответ идёт через тот же безопасный разбор markdown, что и заметки, цитаты открывают заметку.
- Рекомендации. Карточки по видам: идея, задача, связь, привычка. «Создать заметку» переносит текст в форму новой записи, сохраняет её сам пользователь. «Скрыть» только убирает карточку на экране. Переключатель «Рекомендации ИИ» читает и меняет `/settings`. Когда он выключен, блок показывает короткую подсказку, а вопрос и сводка работают.
- Сводка за неделю. Текст, главное с цитатами, открытые задачи и темы.
- Цена и остаток видны у кнопок («Стоит 1 единицу ИИ · осталось 27 из 30», данные из `/provider/usage`). При 429 показывается текст сервера и время до обновления. Когда остаток равен нулю, кнопки выключены.
- Недавние запросы. Последние 10, клик открывает прошлый результат.

Для тестов интервал опроса задаётся `window.assistantPollMs`, предел ожидания `window.assistantMaxWaitMs`.

## Что не проверено

Живой шлюз не вызывался. Адаптер проверен только с подменённым HTTP-транспортом. Качество реальных ответов и подбор заметок на больших архивах нужно смотреть отдельно в окружении владельца. Тесты интерфейса на jsdom написаны без запуска, их проверяет CI. Экраны смотрели в Chromium с подменённым API.
