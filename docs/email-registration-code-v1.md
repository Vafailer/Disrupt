# Регистрация по почте с кодом

Ветка `feature/email-registration-code-v1` от выпуска безопасности.
Новая миграция `d6a18f9c2e40` после `c9e4a1b2d3f6` создаёт только таблицу
ожидающих регистраций. Существующие пользователи не меняются.

Человек вводит почту и пароль, принимает политику, получает шестизначный код.
После подтверждения создаются пользователь с подтверждённой почтой и сессия.
Войти можно по почте или прежнему имени, ID один. Telegram привязывается
к этому же аккаунту существующим механизмом. Автоматического объединения
двух уже существующих аккаунтов нет.

Код действует 10 минут и работает один раз, только в начавшем регистрацию
браузере. После пяти неверных попыток он блокируется. Повторное письмо
можно запросить через минуту, не больше пяти заявок на адрес в час.
Есть ограничения по IP и общий предел заявок 500 за сутки.
В БД лежат хеш пароля и хеши кода и привязки, открытого кода и пароля нет.
Хеш кода включает случайную привязку из HttpOnly cookie. В дампе её нет,
поэтому одного дампа недостаточно для перебора шестизначного кода.
Использованные хеши стираются, записи старше суток удаляются при новых заявках.

Повторная регистрация на занятую почту даёт такой же первый ответ, но не
отправляет письмо и не перезаписывает аккаунт. Ошибка отправки не создаёт
пользователя. Автоматических повторов писем нет.

Включение требует `NOTES_EMAIL_REGISTRATION_ENABLED=true` и настроенной почты.
По умолчанию выключено. Пока флаг выключен, прежняя регистрация по имени
сохраняется. После включения она закрывается, чтобы обойти проверку почты
через старый API было невозможно. Вход существующих пользователей остаётся.

Транспорт готовится по [yandex-mail-v1.md](yandex-mail-v1.md).
`deploy/compose.smtp.yaml` добавляет пароль приложения только в API.
В worker, scheduler и на сервер бота он не передаётся.
Отправку включать после проверки SMTP и доставки с владельцем.

Статус проверки. Прошли 89 тестов почты, Telegram-входа, миграции и шифрования
с fake mailer. Прошли DOM формы, общий веб, аудио и админка. Ruff прошёл.
Контракт сгенерирован на mock без сети. CI проверяет PostgreSQL, миграции,
образы и восстановление. Реальная доставка Яндекса ещё не проверена.
