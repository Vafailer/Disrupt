# Подключение аудио

Рабочая ветка `feature/audio-connect-v1` создана от `0810de4a3dd972d47107601dd041a369869070a7`. В ней есть последние доработки напоминаний и подготовки STT.

Аудиомодули взяты из `codex/audio-intake-v1`, коммит `ac2780a7cdeae2e8e207a8a73e6a487acbe43acc`. `app/audio_storage.py`, `app/audio_process.py` и `app/routes/audio.py` перенесены без правок. Dockerfile и оба Compose тоже взяты из этого коммита. Ветки не сливались, `main` не менялся.

## Что подключено

`create_app` создаёт хранилище с параметрами `NOTES_AUDIO_STORAGE_PATH`, `NOTES_AUDIO_FFMPEG_PATH` и `NOTES_AUDIO_FFPROBE_PATH`. Можно передать своё хранилище для тестов. Router подключён в обычное приложение, отдельное тестовое подключение больше не нужно.

Работают три маршрута.

| Метод | Путь | Назначение |
|---|---|---|
| POST | `/internal/v1/telegram/voice` | Приём голоса от адаптера |
| POST | `/api/v1/captures/audio` | Загрузка из веба |
| GET | `/api/v1/captures/{capture_id}/audio` | Скачивание оригинала владельцем |

В опубликованном контракте они отмечены как реализованные. Сигнатуры и форматы ответов не менялись. Модели и миграции в этом подключении не изменены.

Встроенный worker открывает то же хранилище только для чтения. Отдельный `python -m app.worker` тоже использует read-only хранилище. В Compose API получает постоянный том для записи, worker получает этот том только для чтения.

## Проверки общего кода

Тесты аудиомаршрутов теперь используют настоящий `create_app`, без добавления второго router. Изменено только подключение в двух фикстурах и убрана проверка отсутствия ядра. Сами проверки коллеги сохранены.

Добавлены проверки голоса через настоящий Telegram-адаптер с ASGITransport и работы встроенного worker. Синтетический оригинал сохраняется неизменным, повтор не создаёт второе задание, транскрипт виден в БД до LLM, скачивание остаётся доступным после ошибки STT. Отдельно проверяется read-only хранилище в запуске worker.

CI запускает тесты текущего checkout вместе с PostgreSQL 17. Старого временного checkout ядра `8000234` здесь нет. Отдельный job собирает текущий Dockerfile и проверяет декодеры, каталог аудио и запуск под обычным пользователем.

Локальный общий прогон прошёл с 294 passed и 5 skipped. Пропущены только PostgreSQL-проверки, локальной БД нет. Линтер, Node/jsdom, миграции и повторная генерация контракта прошли. Декодер FFmpeg 6.1.1 на Linux. Docker локально недоступен, его проверяет CI. Статус CI нужно смотреть для опубликованного SHA этой ветки.

Для локальной проверки нужны FFmpeg и FFprobe. Из корня выполнить.

```sh
python -m ruff check app tests migrations scripts telegram_adapter
PYTHONPATH=. python scripts/export_contract.py
python -m pytest -q
```

## Что ещё не готово

Реального STT-провайдера пока нет. Тестовый `MockSpeechProvider` передаётся явно, его текст задаётся в тесте. Без провайдера аудиозадание завершится с `stt_not_configured`, оригинал останется доступным. Текстовый mock не подменяет распознавание аудио.

Кнопки записи и загрузки в вебе, правка транскрипта и Cloud.ru STT остаются нашей задачей. Scheduler и отправка уведомлений остаются у коллеги. На сервере ещё нужно проверить общий запуск и резервное копирование БД вместе с аудиотомом.

Живые Telegram и Cloud.ru не проверялись. Выданный ключ не читался и не использовался. Автоматического объединения с `main` нет.
