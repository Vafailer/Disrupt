# Умные заметки

Проект команды для Sber500 × Disrupt: быстрый сбор мыслей через веб и Telegram, структурирование записей с помощью ИИ и работа с личными заметками в веб-приложении.

## Текущее состояние

Реализован первый текстовый сценарий: аккаунт → исходная запись → фоновая обработка → заметка с базовой разметкой → отдельные возможные выводы → ручные правки и история версий. Есть простая веб-страница для проверки. По умолчанию работает **mock**, без обращений к ИИ.

Cloud.ru подтверждён командой. Его текстовый адаптер написан и проверен с подменой HTTP-транспорта. Настоящий ключ не использовался; доступ к конкретной модели и качество её ответов ещё не проверены. Голос, Telegram и установка PWA пока не реализованы.

## Репозиторий команды

Весь код, миграции, тесты, локальные launchers, Docker-конфигурация и документация находятся в [GitHub-репозитории Vafailer/Disrupt](https://github.com/Vafailer/Disrupt). Основная ветка — `main`. Участники клонируют репозиторий, работают в отдельных ветках и предлагают изменения через pull request; подробные команды приведены в CONTRIBUTING.

Для пользователей API-ключ не нужен. В production-схеме ключ Cloud.ru получает только отдельный worker через Docker Secret; браузер и публичный API-контейнер его не имеют. Пользователь регистрируется, отправляет текст вашему API и забирает обработанную заметку. Готовая конфигурация PostgreSQL + API + worker + HTTPS находится в `compose.production.yaml`.

## Запуск с настоящей нейросетью Cloud.ru

Не отправляйте API-ключ в чат и не записывайте его в `.env`. Остановите уже запущенное демо сочетанием Ctrl+C, затем откройте [start-cloudru.cmd](start-cloudru.cmd) двойным щелчком.

Скрипт попросит три значения:

1. API-ключ Cloud.ru — ввод скрыт, символы не показываются. Ключ хранится только в окружении процесса до остановки сервера.
2. ID модели — можно нажать Enter и использовать `ai-sage/GigaChat3-10B-A1.8B`, указанную в публичной документации Cloud.ru. Если организаторы дали другой ID, введите его.
3. Максимум запросов — по умолчанию 5. Это число обращений к модели, а не токены и не рубли. Одна новая заметка резервирует один запрос. Лимит действует на всю историю отдельной базы `data/cloudru.db`, а не на один запуск. Интерфейс показывает использовано/осталось. Если позже запустить с более высоким лимитом, разница станет доступна; уже использованные запросы не обнуляются.

После запуска откройте **http://127.0.0.1:8000**, создайте новый локальный аккаунт и отправьте запись. Каждая новая запись создаёт одно задание и один запрос к Cloud.ru. Повторная отправка того же HTTP-запроса с прежним ключом идемпотентности не создаёт нового задания. Автоматических платных повторов после тайм-аута или ошибки нет. Ручной повтор после ошибки — новый запрос и новый занятый слот.

Приложение показывает «Cloud.ru подключён» только в live-режиме. Ответ модели проходит строгую проверку JSON; исходная мысль сохраняется до обращения к нейросети. Если модель вернула неправильный формат, заметка не создаётся, а оригинал остаётся в списке заданий.

Скрипт не проверяет ключ при запуске и не расходует запрос на список моделей. Первый расход происходит после нажатия «Структурировать». Если появится ошибка доступа, проверьте ID модели и права ключа. Подробности: [настройка Cloud.ru](docs/cloudru.md).

## Запуск без расходов на модель

Окружение `.venv` уже подготовлено. Для проверки интерфейса без нейросети откройте `start-demo.cmd` двойным щелчком и перейдите на **http://127.0.0.1:8000**. Окно сервера должно оставаться открытым; остановка — Ctrl+C.

1. Создайте локальный аккаунт: имя латиницей от 3 символов, пароль от 10 символов.
2. Нажмите «Попробовать пример», затем «Структурировать».
3. Откройте оригинал, измените заметку, примите или отклоните вывод.
4. Перезапустите приложение: запись и история сохранятся.

Встроенный пример имеет заранее подготовленную структуру и вывод. Для другого текста mock только сохраняет текст с простой разметкой и пустым списком выводов. Это проверка приложения, не демонстрация качества настоящей модели. Страница явно показывает режим.

Launcher принудительно выбирает mock, SQLite и адрес `127.0.0.1`; ключ не нужен и не читается. Данные хранятся в `data/notes.db` и не попадают в Git. Для входа используйте тот же адрес, поскольку origin проверяется.

## Установка с нуля

Нужен Python 3.12. PowerShell из корня репозитория:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
powershell -NoProfile -ExecutionPolicy Bypass -File .\start-demo.ps1
```

Linux/macOS:

```sh
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
export NOTES_PROVIDER=mock
export NOTES_ALLOW_LIVE_REQUESTS=false
export NOTES_DATABASE_URL=sqlite:///./data/notes.db
.venv/bin/python -m alembic upgrade head
.venv/bin/python -m uvicorn app.main:create_app --factory --host 127.0.0.1 --port 8000
```

Интерактивный API: **http://127.0.0.1:8000/docs**. Изменяющие запросы требуют cookie сессии и `X-CSRF-Token`, полученного при входе или из `GET /api/v1/auth/me`. Swagger не подставляет этот заголовок автоматически; для полного сценария удобнее веб-страница или HTTP-клиент.

Для отдельного worker установите `NOTES_AUTO_WORKER=false` у API и запустите `python -m app.worker` с той же БД и режимом провайдера. В локальном launcher worker запускается внутри процесса API; задания при этом хранятся в БД, а не в памяти.

## PostgreSQL в Docker

```sh
docker compose up --build
```

Compose запускает PostgreSQL, миграцию, API и отдельный worker в mock-режиме. Порт приложения доступен только на `127.0.0.1:8000`, порт БД наружу не публикуется. Пароль в Compose — публичный локальный пример, его нельзя использовать в развёртывании для пользователей. Docker/PostgreSQL локально пока не запускались: Docker на машине не найден. Для PostgreSQL добавлена отдельная проверка в GitHub Actions, которая выполнится после публикации кода.

## Проверки

```powershell
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m ruff check app tests migrations
.\.venv\Scripts\python.exe -m alembic check
```

Тесты проверяют полный цикл записи, историю, конфликты версий, изоляцию пользователей, CSRF, сессии, идемпотентность, сбои модели, потерю worker, конкурентное получение задания, лимиты и контракт Cloud.ru. HTTP-транспорт и внешние Python socket-соединения блокируются; внутренний socketpair asyncio разрешён для работы тестов на Windows. Проверки Cloud.ru используют только вымышленный ключ и `httpx.MockTransport`.

Опциональный тест PostgreSQL включается переменной `TEST_POSTGRES_URL` для отдельной локальной тестовой БД. Её миграции и тестовые записи не предназначены для рабочей БД. В CI используется одноразовая БД без модельных секретов.

## Основные endpoints

| Метод и путь | Назначение |
| --- | --- |
| `GET /health` | Состояние БД и режим; без обращения к модели |
| `POST /api/v1/auth/register`, `/login`, `/logout` | Аккаунт и сессия |
| `GET /api/v1/auth/me` | Аккаунт и CSRF-токен |
| `POST /api/v1/captures/text` | JSON `{"text":"..."}` + `Idempotency-Key`; возвращает `202` и задание |
| `GET /api/v1/jobs`, `/api/v1/jobs/{id}` | Последние задания, статус, сохранённый исходник и ID заметки |
| `GET /api/v1/notes` | Список своих заметок, `limit` / `offset` |
| `GET /api/v1/notes/{id}` | Оригинал, результат, выводы и версия |
| `PATCH /api/v1/notes/{id}` | `version`, `title`, `markdown`; конфликт — `409` |
| `PATCH /api/v1/notes/{id}/conclusions/{conclusion_id}` | `version`, `status`: `accepted` или `rejected` |
| `GET /api/v1/notes/{id}/revisions` | Последние 100 версий |

Исходник сохраняется до обработки. Для повторной отправки того же запроса используйте прежний `Idempotency-Key`; другой текст с прежним ключом отклоняется. Ключ действует в пределах аккаунта. Ошибка или перезапуск во время обработки не приводят к автоматическому повторному обращению к модели: задание получает явный статус ошибки, исходник остаётся в списке заданий. Очередь сохраняет новые задания после перезапуска.

## Первый пользовательский сценарий

Пользователь вводит поток мыслей и получает заметку с сохранённым смыслом, понятной структурой и базовой Markdown-разметкой. Отдельный блок содержит возможные выводы ИИ, которые пользователь может принять или отклонить. Исходник сохраняется. Голосовые сообщения проходят распознавание перед тем же процессом. Telegram служит каналом добавления записей; просмотр и редактирование доступны в вебе. Поиск и чат по заметкам отложены за пределы первого демо.

## Разработка без расходов на модель

Выданный лимитированный API-токен агентам использовать запрещено. Разработка и CI должны использовать только mock-провайдеры. Они имитируют ответы для проверки сценариев и не подтверждают качество настоящего ИИ. Доступ к реальному провайдеру и распознавание на нём требуют отдельной проверки командой; агент таких запросов не выполняет.

## Предлагаемый стек

Python + FastAPI, SQLAlchemy + Alembic, pytest. SQLite для простого локального запуска, PostgreSQL для серверного варианта. Зависимости зафиксированы в `requirements.txt`. API и worker находятся в одном проекте; провайдер не получает прямого доступа к БД.

Перед внешним пользовательским пилотом остаются настройка HTTPS и доступа, резервное копирование, закрытие регистрации после создания тестовых аккаунтов, проверка PostgreSQL и ручная проверка настоящей модели командой. Текущая версия — локальный текстовый прототип. Аналитика конкурса, аудио, Telegram, восстановление пароля, поиск и полноценная PWA ещё не реализованы.
