# Умные заметки

Мы делаем приложение, которое помогает записать мысль как есть, привести её в порядок и заметить возможные выводы. Оригинал остаётся у пользователя. Выводы ИИ показываются отдельно, их можно принять или отклонить.

Сейчас работает текстовый сценарий. Пользователь входит в аккаунт, отправляет запись, получает заметку с Markdown-разметкой, правит её и видит историю изменений. Для проверки есть простая веб-страница. Голос, Telegram и установка PWA ещё не готовы.

По умолчанию приложение использует `mock` и не обращается к нейросети. Адаптер Cloud.ru написан и проверен с подменёнными HTTP-ответами. Доступ выданного ключа к модели и качество реальных ответов команда пока не проверяла.

## Попробовать без API-ключа

На Windows откройте `start-demo.cmd` двойным щелчком. Если Python-окружения ещё нет, сначала выполните в PowerShell из корня репозитория:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\start-demo.cmd
```

Откройте `http://127.0.0.1:8000`. Зарегистрируйтесь, нажмите «Попробовать пример» и затем «Структурировать». Можно открыть исходный текст, изменить заметку и принять или отклонить вывод. После перезапуска данные останутся в `data/notes.db`. Окно сервера должно оставаться открытым; для остановки нажмите Ctrl+C.

Для произвольного текста `mock` сохраняет простую разметку без выводов. Это позволяет проверить работу приложения, но ничего не говорит о качестве настоящей модели.

На Linux или macOS запуск выглядит так:

```sh
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
export NOTES_PROVIDER=mock
export NOTES_ALLOW_LIVE_REQUESTS=false
export NOTES_DATABASE_URL=sqlite:///./data/notes.db
.venv/bin/python -m alembic upgrade head
.venv/bin/python -m uvicorn app.main:create_app --factory --host 127.0.0.1 --port 8000
```

## Проверить с Cloud.ru

Владелец ключа может запустить `start-cloudru.cmd` на своём компьютере. Скрипт попросит ключ скрытым вводом, ID модели и общий лимит обращений. По умолчанию лимит равен `5`. Это число запросов к модели за всё время существования отдельной базы `data/cloudru.db`, а не количество токенов или сумма в рублях. Уже занятые запросы не обнуляются после перезапуска.

Не отправляйте ключ в чат и не добавляйте его в `.env` или Git. Скрипт не проверяет ключ при запуске. Первый запрос к Cloud.ru произойдёт, когда вы отправите запись на обработку. Перед этим проверьте, что ID модели доступен вашему ключу. Подробности есть в [инструкции по Cloud.ru](docs/cloudru.md).

Если ответ модели содержит ошибку или неверный формат, исходная запись сохранится, а задание получит статус ошибки. Автоматических повторных обращений к модели нет. Ручной повтор с новым ключом идемпотентности может потратить ещё один запрос.

## Как устроен доступ к модели

Пользователю API-ключ Cloud.ru не нужен. Браузер отправляет текст нашему серверу. Сервер сохраняет запись и задание в базе, а отдельный worker обращается к модели и записывает результат. При серверном развёртывании секрет доступен только worker через Docker Secret. Подготовленная конфигурация с PostgreSQL и HTTPS описана в [инструкции по развёртыванию](docs/deployment.md).

Для локальной проверки PostgreSQL в Docker можно выполнить:

```sh
docker compose up --build
```

Это запускает API, PostgreSQL и worker в режиме `mock`. Docker на машине разработки отсутствует, поэтому локальный запуск Compose пока не подтверждён.

## API и проверки

Документация API доступна по адресу `http://127.0.0.1:8000/docs`. Для запросов, которые меняют данные, нужны cookie сессии и `X-CSRF-Token` из ответа при входе или из `GET /api/v1/auth/me`. Swagger сам этот заголовок не подставляет.

Запись отправляется через `POST /api/v1/captures/text` с `Idempotency-Key`. Метод возвращает задание, состояние которого видно по `GET /api/v1/jobs/{id}`. Готовые заметки можно получить через `GET /api/v1/notes` и `GET /api/v1/notes/{id}`. Ручные правки и решения по выводам выполняются через `PATCH` с проверкой версии. Полный сценарий описан в [плане бэкенда](docs/backend-plan.md).

```powershell
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m ruff check app tests migrations
.\.venv\Scripts\python.exe -m alembic check
```

Тесты используют вымышленный ключ и подменённый HTTP-транспорт. Выданный команде лимитированный токен при разработке и проверках не используется. Результаты уже выполненных проверок записаны в [docs/verification.md](docs/verification.md).

При неожиданной ошибке API или сбое обработки приложение пишет запись в `data/errors.log`. Там есть время, код ошибки, место в коде и ID задания или запроса, по которому можно найти нужную запись. Текст заметки, ключ и сообщение исключения в лог не попадают. Файл ограничен 1 МБ, старые записи хранятся в трёх копиях. Путь можно изменить через `NOTES_ERROR_LOG_FILE`; пустое значение оставит только вывод в журнал процесса. На сервере ошибки также видны через `docker compose --env-file .env.production -f compose.production.yaml logs api worker`.
